# Pulse CRM audit — 2026-09-30

Live app: https://pulse-crm-weld.vercel.app (open-access guest mode, commit `8fd27ce`).

**Method.** Walked every route in the in-app browser as a fresh guest (desktop and phone width), read console errors and network responses, and tested the AI Copilot end to end. Two code sweeps ran in parallel: one for fake data and dead controls, one for production readiness. Every item below was checked against the code; false alarms are listed at the end.

**Verdict.** The core CRM works: all 39 routes load, the seeded workspace renders, leads, deals, customers, sequences and analytics show real data, and the phone layout holds. What's missing is mostly *honesty*: a lot of the UI looks finished but is fake or silent. A first-time visitor hits fake numbers on the first screen, buttons that do nothing, and an AI assistant that never answers and never says why.

- **13 dashboard sections have no `loading.tsx`**, so sidebar clicks look frozen: analytics, campaigns, competitors, contacts, copilot, icp, inbox, marketing, playbook, proposals, sequences, templates, website-visitors.

## 6. Security and data

- **13 tables were created by hand in production** and no repo migration defines them: `apify_scraper_runs, campaign_tags, copilot_conversations, copilot_memory, copilot_messages, copilot_tasks, lead_searches, scraped_leads, sequence_email_accounts, sequence_tags, tracking_scripts, website_visitors, website_visits`. A fresh database can't be built from the repo, and `20260313_automation_rules.sql` fails on one because it alters two of them. Verified live: none returns rows to an anonymous caller. **Still to verify:** that a signed-in guest can't read another workspace's rows. Run this in the Supabase SQL editor (read-only):

  ```sql
  SELECT c.relname, c.relrowsecurity AS rls_on,
         coalesce(json_agg(json_build_object('name', p.policyname, 'cmd', p.cmd, 'using', p.qual))
                  FILTER (WHERE p.policyname IS NOT NULL), '[]') AS policies
  FROM pg_class c
  LEFT JOIN pg_policies p ON p.tablename = c.relname AND p.schemaname = 'public'
  WHERE c.relnamespace = 'public'::regnamespace
    AND c.relname IN ('apify_scraper_runs','campaign_tags','copilot_conversations','copilot_memory',
                      'copilot_messages','copilot_tasks','lead_searches','scraped_leads',
                      'sequence_email_accounts','sequence_tags','tracking_scripts',
                      'website_visitors','website_visits')
  GROUP BY c.relname, c.relrowsecurity ORDER BY 1;
  ```
  Then dump their DDL and policies into migration 032 so the repo matches production.
- **Copilot mutations filter by `id` only**, not organization. Safe only if the RLS above is correct; add `.eq("organization_id", orgId)` regardless. `lib/actions/copilot.ts:40-60,147-190,359-395`
- **Avatar uploads:** no type or size check, the bucket is public, and the insert policy only requires "authenticated" (which every anonymous guest is). Anyone can host arbitrary public files. `lib/actions/profile.ts:54`, `supabase/migrations/001_initial_schema.sql:505`
- **Public API** uses one shared key and a caller-chosen organization header with the service role, so the key holder can read every tenant. `lib/api-auth.ts:39`. Move to per-organization keys before sharing it with anyone.
- **Gmail callback** reports success even if saving fails, and its `state` is the user id rather than a random value. `app/api/email/oauth/google/callback/route.ts:71`
- **Stale fallback URL** `pulse-crm-rosy.vercel.app` in three places. `lib/ai/client.ts:40`, `app/api/linkedin/oauth/route.ts:20`, `website-visitors/client.tsx:153`
