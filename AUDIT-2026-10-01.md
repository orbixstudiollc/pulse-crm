## Fix plan (grouped by root cause)

### P0: broken or visible to every user

1. **Opening a proposal leads to a 404** (B, blocker). `app/dashboard/proposals/client.tsx:449,493` links to `/dashboard/proposals/[id]`, which does not exist. Fix: build the proposal detail page using the Clay detail layout.
2. **Demo data categories don't match the UI's ids** (B, A; five symptoms). The seed stores labels and the tabs filter on ids:
   - Templates: every category tab is empty.
   - Sequences: the Nurture tab is empty.
   - Playbook: the Pricing count is 0.
   - Competitors: Direct, Indirect and Aspirational are 0.
   - Contacts: every role tab is empty.
   - ICP: criteria are blank and pain points read "Severity: undefined".

   Fix both ends. In `lib/seed/generate.ts`, emit the ids and shapes the UI expects. In the UI, normalize categories in one place so existing workspaces also display correctly. Every guest workspace already created carries the old values.
3. **Background jobs are not running** (D, 2 high). The GitHub Actions `*/5` schedule has fired once in total. The worker step also has a typo, `--max-time 300-H`, so every call is sent without auth and returns 401. The Lead Finder worker, automations and sequence sends are therefore not happening. Fix the typo now. The schedule needs a decision:
   - an external scheduler (cron-job.org or Upstash QStash) calling the cron routes with `CRON_SECRET`, or
   - Vercel Pro crons. Hobby allows daily crons only.
4. **Copilot floating button covers content** (C high, A medium). It covers:
   - pagination on list pages on phones
   - drawer footer actions (View Full Profile, View Details, Mark Complete)
   - "Upgrade Now" in Billing

   It also has no `aria-label`. Fix: bottom padding on `<main>` equal to the button's size, the button tucked below drawers and modals, and an `aria-label`.
5. **Enrichment status polled every 2 s** (A, high). `/api/lead-finder/enrichment-status` is polled on every dashboard page, with 3–19 s responses and up to 13 requests in flight. This is the likely cause of 8–20 s client navigations to detail pages. Fix: poll only while a batch is active, back off, and never overlap requests (`components/lead-finder/EnrichmentProgressBanner.tsx`).
6. **Wrong numbers** (A, high):
   - The Analytics header shows "D-to-C 120%", because customers are divided by deals.
   - The customer drawer shows LTV $0 and Tenure 0 while the detail page shows $20.5K and 1 month. Both tenures are wrong.

### P1: platform and security

- **Guest workspaces:**
  - Open access creates a guest workspace for any cookie-less GET, including uptime monitors, link checkers and `curl`. There are now 116 guest orgs holding about 9.6k rows, up from 80 yesterday. Fix: provision only for `GET` requests from real browsers (`Accept: text/html` plus a fetch-metadata check) in `lib/supabase/middleware.ts`.
  - Guest cleanup (7-day retention via the daily cron) is in the code but hasn't run yet. The first purge is due around Oct 5–6; verify it then.
- **Destructive buttons for guests.** Settings → Profile offers "Clear All Data" and "Delete My Account" to guests in one tap. They are scoped to the guest's own workspace, but consider hiding them while open access is on.
- **The public API is live on one shared key.** It uses a single `PULSE_CRM_API_KEY` and a caller-chosen `x-organization-id` (`lib/api-auth.ts`). This is still open from 09-30. Fix: per-organization API keys.
- **The CSP is only `frame-ancestors`.** Add `default-src`, `script-src` with nonces, `object-src 'none'` and `base-uri`.
- **Repo gaps:**
  - The 13 hand-made tables still have no migration, so a fresh database can't be built from the repo. That migration needs a new number, because 033 is used.
  - The cross-tenant read check for signed-in guests is still outstanding.
  - `.env.example` is git-ignored by `.env*` and doesn't list the open-access and guest settings.
